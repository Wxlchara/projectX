# VisaPilot — работа Матвея и Вани с разных компьютеров

## Общая схема

У каждого своя локальная копия одного GitHub-репозитория, отдельная ветка и собственная работа с Codex. GitHub передаёт исходники и документацию после commit/push, но не несохранённые правки, процессы приложения или содержимое чата другого участника.

Для начала работы Codex достаточно прочитать документацию из репозитория и получить конкретное задание/роль. Полную историю этого чата переносить не требуется.

Полная изоляция по времени невозможна: модули зависят от общих интерфейсов. Начальная общая точка — каркас, схемы и контракт пакета 1; затем работа идёт параллельно с короткими интеграциями.

## 1. Что положить в GitHub

В корень общего репозитория:

- Весь каталог docs, включая source и готовые prompts.
- Корневой .gitignore.
- В дальнейшем — исходники backend, frontend, тесты и вымышленные SAMPLE-образцы.

Служебные файлы IDE, окружение .venv, local_data, SQLite-базы, .env и авторизация CLI не передаются. Нужные переменные показываются без значений секретов в .env.example. Вымышленные образцы в demo можно хранить в Git — папка не исключена.

В GitHub нужно добавить Ваню и frontend-разработчика как collaborators с доступом к записи. Для репозитория команды можно выбрать private. Ссылка на репозиторий сама по себе не выдаёт доступ к закрытому проекту.

## 2. Начальная загрузка

Текущая папка с документами на момент этой инструкции ещё не является Git-репозиторием. Никакая публикация из этого чата не выполнялась.

**Если общего репозитория ещё нет:** создать новый пустой репозиторий на GitHub; после этого в этой папке выполнить команды ниже, подставив настоящий URL. Эти команды — инструкция, а не уже выполненные действия.

```bash
git init -b main
git add .gitignore docs
git commit -m "docs: finalize VisaPilot scope and implementation plan"
git remote add origin <URL_ВАШЕГО_РЕПОЗИТОРИЯ>
git push -u origin main
```

**Если репозиторий уже есть и содержит frontend/другой код:** клонировать именно его и скопировать docs/.gitignore туда. Существующий .gitignore дополнить, не заменить. Не создавать вторую независимую main поверх существующей истории. Затем сделать обычный commit/push в разрешённой рабочей ветке и объединить изменение через pull request.

## 3. Как Ване начать

После получения доступа:

```bash
git clone <URL_ВАШЕГО_РЕПОЗИТОРИЯ>
cd <ПАПКА_РЕПОЗИТОРИЯ>
git switch -c vanya/05-documents
```

Открыть эту локальную папку в Codex и передать стартовый запрос из раздела ниже. Рабочая ветка начинается от актуальной main; до начала реализации проверить git status.

Матвей аналогично создаёт свою ветку от main, например matvey/01-foundation. Для следующих самостоятельных изменений лучше создавать короткие ветки по пакетам: matvey/11-auth, matvey/04-cases, vanya/06-checks. Frontend — отдельная ветка и каталог, например frontend/site.

## 4. Что делать параллельно в начале

Матвей реализует пакет 1 и быстро объединяет его в main. Ваня в это время подготавливает обработку образцов/зависимости и интерфейс AI-адаптера; не придумывает другую версию общих моделей. После появления каркаса Ваня получает новую main в свою ветку и подключает пакет 5. Матвей продолжает с 11 и ядром.

Авторизация CLI через ChatGPT фактически проверена только на ноутбуке Матвея. Живой AI-запрос для проверки этого окружения запускает Матвей; Ваня реализует адаптер и может проверять контракт локальной фикстурой/своим доступом, если он есть. Подписка для написания кода и доступ AI внутри запускаемого VisaPilot — разные вопросы. Передавать авторизацию Матвея через GitHub не требуется.

Общие app/main.py, app/common/, схема БД и контракт принадлежат Матвею. Ваня работает в app/documents, app/ai, app/checks, app/itinerary, app/letters и интеграционных тестах. Если нужен новый общий столбец/поле/endpoint, сначала согласовать изменение и внести его владельцем контракта.

## 5. Как передавать готовое изменение

1. Агент показывает git diff и результаты проверок. В рабочей ветке сохраняются только изменения своего пакета.
2. Сделать commit и push ветки. Например, для Вани:

```bash
git add app/documents app/ai
git commit -m "feat: add personal document archive and extraction"
git push -u origin vanya/05-documents
```

Пути приведены для уже созданных файлов пакета; свои тесты добавить отдельными фактическими путями. Не включать несвязанные изменения.

3. Открыть pull request в main. Кратко указать пакет, реализованные endpoints, изменения контракта и фактически выполненные проверки.
4. Для хакатона Матвей координирует объединение: проверяет совместимость/запуск и объединяет PR. Не требуется ждать окончания всех пакетов.
5. Остальные получают main. Это стандартная схема веток и pull requests: [GitHub flow](https://docs.github.com/en/get-started/using-github/github-flow).

Синхронизация — после готового пакета или рабочего шага примерно каждые 20–30 минут. Примеры коротких сообщений команды: «каркас в main», «архив готов, PR открыт», «полю нужен новый тип, контракт сначала меняем в main».

## 6. Как получить изменения main

Сначала сохранить свои законченные изменения коммитом в своей ветке. При чистом рабочем дереве:

```bash
git fetch origin
git merge origin/main
```

После этого проверить свой модуль и push. Для четырёхчасовой командной работы merge актуальной main в рабочую ветку проще, чем переписывать уже опубликованную историю. Force-push и удаление чужих правок не нужны.

Для новой задачи после объединения предыдущей ветки:

```bash
git switch main
git pull --ff-only origin main
git switch -c <НОВАЯ_РАБОЧАЯ_ВЕТКА>
```

Перед переключением ветки рабочее дерево должно быть чистым. Если есть конфликт, Codex получает задачу согласовать обе реализации по docs/contracts.md, а не выбрать одну сторону целиком.

## 7. Данные и запуск

На каждом компьютере своя локальная БД и свои загруженные файлы. Их не синхронизируют через Git. В репозиторий входят исходники, схемы, инструкции и вымышленные образцы/команда наполнения.

Финальный показ собирается из main на ноутбуке Матвея с его существующим CLI-входом. Ваня и frontend-разработчик могут локально запускать собственные копии для разработки. Лишь для совместного показа браузеры обращаются к одному работающему серверу по адресу ноутбука в LAN.

## Стартовый запрос Codex для Матвея

```text
Я Матвей, работаю над backend VisaPilot в своей ветке общего репозитория.
Прочитай docs/README.md, docs/concept.md, docs/contracts.md,
docs/engineering-decisions.md, docs/implementation-plan.md и docs/team-workflow.md.
Проверь git status и текущую ветку; сохрани существующие чужие изменения.
Мои пакеты: 1, 11, 2, 3, 4, 9. Общие модели, схема БД и app/main.py — моя зона.
Начни с пакета 1 по готовому запросу в docs/prompts.md. Подготовь минимальный
запускаемый каркас и общие интерфейсы для Вани/frontend. Зафиксируй первый
рабочий результат отдельным коммитом в моей ветке; в конце покажи проверки
и что нужно передать в main. Не реализуй модули Вани и frontend.
```

список файлов, результат проверок и требуемые изменения общего контракта.
