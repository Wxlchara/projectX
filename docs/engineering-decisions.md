# VisaPilot — инженерные решения для реализации

Статус: выбранные агентом технические решения в пределах согласованной [концепции](concept.md). Это не дополнительные обещания публичного продукта. Конкретные установленные версии зависимостей фиксируются при первом успешном запуске.

## 1. Стек и процессы

Python 3.12, FastAPI, Pydantic 2, Uvicorn; стандартный sqlite3 для БД; pwdlib с Argon2 для паролей; pypdf для PDF-текста; pypdfium2 для растеризации сканированных PDF; Pillow и Tesseract для изображений/OCR. Проверки — обычные Python-функции. pytest и httpx — для значимых проверок API и изоляции данных.

Один backend, один процесс Uvicorn. SQLite с foreign_keys=ON, WAL и короткими транзакциями; отдельное соединение на операцию. Долгая OCR/AI-обработка не удерживает транзакцию БД. Redis, Celery, Kafka, отдельный сервер БД и распределённые микросервисы не нужны для этой установки.

Распознавание и AI вызываются асинхронно относительно основного цикла HTTP-сервера; для демо API возвращает результат того же запроса. Максимум одна обработка документа и один AI-запрос одновременно; второй такой запрос получает явный ответ «занято». PDFium защищён общим mutex: его нельзя одновременно вызывать из разных потоков.

## 2. Кабинет, вход и владение

Регистрация по username и паролю, вход, выход, получение текущего пользователя. Подтверждение email, восстановление по письму, социальный вход и 2FA не входят в демо. Пароль хранится только как Argon2-хеш.

Серверная сессия: случайный токен из secrets, его хеш и срок действия 12 часов в SQLite; токен в HttpOnly cookie с SameSite=Lax. Logout отзывает сессию. Для изменяющих авторизованных запросов — X-CSRF-Token, привязанный к сессии; токен отдаётся при входе и GET /auth/me. В LAN HTTP для синтетического демо Secure=false; при HTTPS Secure=true. Frontend и API имеют общий origin; в разработке frontend использует proxy к /api.

Каждая операция с профилем, делом, файлом, проверкой или текстом получает владельца из текущей серверной сессии. Клиент не назначает owner_id. Чужой идентификатор возвращает 404; отсутствие входа — 401. Проверяется также принадлежность обоих объектов при прикреплении документа к делу.

## 3. Архив и файлы

Метаданные и поля — SQLite; бинарные файлы — local_data/uploads вне каталога публичной статики. Имена хранения генерируются сервером. Исходное имя — только отображаемое поле. Скачивание — исключительно через авторизованный endpoint, без выдачи пути файловой системы.

Поддержка: PDF, JPEG и PNG; до 10 MiB и 10 страниц на файл; изображения до 20 мегапикселей. Проверяются фактический формат, декодирование и ограничения. Зашифрованный PDF, повреждённый файл или превышение лимита дают понятную ошибку.

Сначала извлекается PDF-текст; для страниц без текста выполняются ограниченная растеризация и локальный OCR. Один файл обрабатывается не дольше 60 секунд; затем сохраняется ясное состояние неполной обработки с возможностью вручную заполнить/подтвердить поля. Tesseract с русским и английским языками устанавливается до демо.

Загруженный вымышленный оригинал сохраняется до удаления владельцем/сброса демо; временные изображения OCR удаляются. Удаление документа удаляет оригинал, текст и поля, снимает связи с делами, делает связанные результаты неактуальными и пересчитывает чек-листы. Удаление дела отвязывает документы, но сохраняет личный архив.

Каждая новая загрузка — новый document_id; файл под существующим ID не перезаписывается. Поля можно исправлять с увеличением facts_revision. Прикрепление одного файла к двум делам не копирует результат проверки между ними.

## 4. Профиль и анкета

Один профиль заявителя на аккаунт, несколько дел. В профиль входят подтверждённые имя/фамилия латиницей, дата рождения, гражданство, страна проживания, второе гражданство/ВНЖ, тип и даты паспорта, статус занятости, сведения об имеющихся разрешениях при необходимости. Номер паспорта не нужен для сравнения стран; его не следует требовать заранее.

В дело входят цель, страна, даты, город отправления, предполагаемое место подачи, проживание/финансирование и маршрут. Дополнительные поля запрашиваются только при применимости правила. Булевы ответы допускают null: неизвестно не равно false. Неподдерживаемый заявитель получает unsupported_profile с причинами.

Изменение профиля увеличивает profile_revision и делает затронутые результаты дел устаревшими. Подтверждение полей привязано к их ревизии.

## 5. Реестр и применимость

Правила хранятся в версионируемых JSON-файлах, валидируются Pydantic и загружаются приложением. По 12 странам готовит данные владелец пакета 2; по Турции/ОАЭ — владелец пакета 7. Редактор UI и автоматический краулер исключены из демо.

Правило содержит id, version, scenario_id, kind, applies_if, параметры проверки, обязательность, source_ids. Источник содержит URL, название органа, checked_at, review_after и статус source_checked/needs_verification/conflicting. checked_at заполняется только после фактического открытия/сопоставления источника. Целевая дата пересмотра — инженерный срок, а не гарантия юридической актуальности.

applies_if — небольшой фиксированный набор all/any и сравнений eq, in, exists, gte/lte; без eval и исполняемого кода в JSON. Отсутствующий ответ даёт needs_input; непроверенный/конфликтующий источник — needs_verification. Неизвестное условие не приводит к успешному результату.

В работе используется версия набора правил и ревизии данных. Пересчёт после изменения анкеты, документа или набора правил помечает предыдущие результаты устаревшими и показывает причину. Обновление набора правил — загрузка новой проверенной версии и перезапуск приложения; существующие дела переоцениваются при обращении к ним. Автоматических заявлений «правила обновились сегодня» без проверки нет.

## 6. Сравнение и замечания

Сравнение возвращает по каждой стране режим выбранного сценария, применимость, известные препятствия, требования и отдельные факторы: объём обязательного пакета, внешние действия, маршрут и неопределённость. Нет совокупного «шанса визы» или универсального дохода. Страна с непроверенными условиями не ранжируется как самая простая по отсутствующим данным.

Замечание содержит стабильный code, severity (blocking/fix/verify/info), message, next_action, document_ids, field_paths, rule_id/version либо origin=heuristic. Оно привязано к case_id и ревизиям входов.

Проверяются только реально полученные поля. Регистры и пробелы в именах нормализуются; неоднозначная транслитерация даёт verify. Разные валюты без подтверждённого курса не сравниваются. Суммы — Decimal/строки и ISO-код валюты. Требования в календарных месяцах рассчитываются календарно, а не заменяются произвольным числом дней.

## 7. Готовность и этапы

Пункт имеет kind=document/preparation_action/process_action и readiness_contributing. В готовность пакета входят обязательные применимые документы и действия подготовки; внешние этапы подачи туда не входят.

Состояния пункта: missing, received, issues, needs_verification, satisfied, not_applicable. satisfies означает выполненное требование с указанным способом проверки: rules_checked или user_confirmed для пунктов вне автоматической проверки. Пользовательская отметка не скрывает блокирующее замечание и не превращает непроверенное правило в подтверждённое.

readiness_percent = floor(100 * satisfied_required / applicable_required). Условные пункты включаются после определения применимости; рекомендованные в знаменатель не входят. Неизвестная обязательная применимость блокирует ready=true; даже при 100% закрытых известных пунктов отображается «есть непроверенные условия». Если знаменатель пустой или сам набор требований неизвестен — percent=null, ready=false, needs_verification.

Пакет готов только при 100%, подтверждённых ключевых полях, отсутствии блокирующих/требующих исправления замечаний и непроверенных обязательных условий. Изменение документа или даты может уменьшить готовность.

process_percent = floor(100 * completed_applicable_stages / applicable_stages). Шаблоны различаются для визы, e-Visa и безвизовой подготовки. Этапы подтверждаются ручными событиями/действиями, а не процентом документов. Пропуск допускается только если этап неприменим по шаблону. Позднее событие не подтверждает молча все предыдущие.

outcome=unknown/approved/refused/not_applicable хранится отдельно. Для visa/e-Visa decision_received требует явно указанного исхода; passport_returned его не устанавливает. Для безвизовой подготовки outcome=not_applicable.

## 8. AI, письма и резервный режим

Один общий адаптер Codex CLI: входные синтетические факты/текст, структурированный JSON-выход; вызов без shell-интерполяции, через список аргументов/stdin. Отдельная рабочая папка, read-only sandbox, минимальная конфигурация; не выполнять команды из содержимого документов. Сохранённые credentials не читаются приложением и не копируются в репозиторий: CLI использует собственный вход.

Стартовый запрос проверяет доступ и выбранную модель. Нового платного ключа и автоматического перехода на платный API нет. Тайм-аут AI 60 секунд, максимум один автоматический повтор только при временной ошибке; ошибки лимита/входа не ретраятся циклом. Повторное использование ответа допустимо только при совпадающих входах, версии шаблона и модели; ответ помечается from_cache.

AI не пишет нормативные правила и не закрывает требования по собственному предположению. Проверки дат, сумм и применимости детерминированы. При недоступности AI кабинет, OCR и проверки продолжают работать; пояснение локальное, письмо — явно обозначенный шаблон или сообщение о недоступности.

Для демо: интерфейс и пояснения на русском, черновик сопроводительного письма на английском, редактирование и сохранение текста, скачивание UTF-8 .txt. Юридическая пригодность письма для любого органа не обещается. Недостающие факты перечисляются отдельно, в текст не вставляются фиктивные сведения. PDF/DOCX-экспорт вне четырёх часов.

## 9. Маршрут и события

Маршрут состоит из участков и пересадок. Сохраняются страна/аэропорт, даты, единый/раздельные билеты, выход из транзитной зоны, получение багажа, имеющиеся разрешения. Неизвестный параметр сохраняется как null. База содержит только явно покрытые правила Турции и ОАЭ; для остальных — needs_verification. flight_availability=not_checked всегда, пока нет источника реальных расписаний.

Ручное событие содержит event_type, occurred_at, received_at, source=manual, note и явно заданный outcome при необходимости. Уведомления — список новых замечаний/событий и следующих действий внутри кабинета; нет внешней доставки, фонового планировщика или обещания внутренних консульских статусов.

Перед вылетом пользователь может повторно запустить те же доступные проверки; круглосуточная помощь в дороге не входит в прототип.

## 10. Важные проверки реализации

- Два аккаунта: запрет чужого файла/поля/дела/события/письма и запрет прикрепления чужого документа.
- Сохранность кабинета после перезапуска; logout отзывает сессию.
- Один документ в двух делах с разными датами получает разные результаты.
- Замена/удаление/правка полей отменяет устаревшее положительное состояние.
- Неизвестное обязательное правило, пустой знаменатель и низкая уверенность OCR не дают ложную готовность.
- Расхождение имён/дат, недостаточная территория полиса и несовпадающая валюта дают корректные замечания.
- Паспорт возвращён без исхода — outcome остаётся unknown; безвизовый сценарий не требует подачи.
- Все 12 направлений проходят общий путь, покрытый транзит отличается от неизвестного.
- AI timeout/исчерпанный лимит даёт честный резервный режим без платного вызова.
