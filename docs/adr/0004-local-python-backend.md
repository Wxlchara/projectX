# ADR-0004 — Python-backend и локальный запуск

Дата: 25 октября 2026 года.

Статус: выбрано агентом в рамках поручения подобрать подходящую реализацию и запуск. Не выдаётся за дословное утверждение пользователем каждой технологии.

## Контекст

Пользователь и Ваня знают Python; C++ доступен при необходимости. Есть четыре ноутбука, ChatGPT Plus, планируется локальное демо. Пользователь допустил Docker и поручил: «сделай так как будет лучше».

Уточнение раунда 2: фронтендер делает работающий сайт через Codex с использованием Figma и подключает API. Конкретный frontend-стек не сообщён. Новые расходы на AI исключены.

## Варианты

1. Несколько микросервисов с отдельным запуском и сетевыми контрактами.
2. Один backend с предметными модулями, одним API и локальным хранилищем.
3. Полностью ручная демонстрация без собственного работающего backend.

## Решение

Выбран второй вариант:

- Python и FastAPI для HTTP API.
- SQLite для дел, состояний, извлечённых фактов и событий в пределах согласованной политики данных.
- Отдельные предметные модули внутри одного приложения; задания агентам соответствуют модулям, а не обязательно отдельным процессам.
- Один обслуживающий ноутбук; браузеры на других ноутбуках обращаются к приложению по локальной сети. SQLite находится на локальном диске обслуживающего ноутбука, не на общем сетевом диске.
- Основной запуск через Python-окружение на ноутбуке с авторизованным Codex CLI. Docker Compose — дополнительная упаковка после рабочего сквозного сценария, не условие готовности AI-демо.
- После получения исполняемого фронтенда — общий адрес приложения и API; способ отдачи статических файлов уточняется по его сборке.
- AI подключается через отдельный интерфейс провайдера: для демо выбран вызов Codex CLI с существующим входом ChatGPT. На демо будет интернет. Модель выбирается из доступных аккаунту и проверяется стартовым запросом во время реализации. [ADR-0005](0005-zero-additional-ai-budget.md).

Отдельные PostgreSQL, Redis, брокер сообщений и распределённое развёртывание для установленной границы демо не нужны. Это техническое сокращение инфраструктуры при сохранении согласованного пользовательского сценария.

## Последствия

- Два разработчика могут реализовывать отдельные модули, заранее согласовав структуры данных и внутренние интерфейсы.
- FastAPI предоставляет OpenAPI и интерактивную документацию, которую можно использовать для интеграции с фронтендом.
- Небольшой локальный сценарий не требует отдельного сервера БД. При изменении нагрузки или числа процессов выбор хранилища пересматривается.
- Переезд между ноутбуками требует переноса конфигурации и выбранного набора демоданных; секреты не входят в репозиторий.
- Отдельная локальная языковая модель не входит в основной путь. Извлечение текста и детерминированные проверки работают локально.
- Docker проверяется, если команда успевает его добавить после сквозного сценария. Авторизация CLI не встраивается в образ и не копируется в репозиторий.
- Этот ADR не разрешает передачу реальных документов внешнему AI и не выбирает политику хранения данных.

## Причина уточнения после раундов 2–3

Приоритет локального Python-запуска выбран после подтверждения нулевого бюджета и использования существующего Plus. Проверка текущего ноутбука обнаружила установленный CLI и вход через ChatGPT; запуск из того же пользовательского окружения уменьшает работу с контейнерной авторизацией. Работоспособность AI-вызова ещё предстоит проверить при реализации.
