# VisaPilot — план реализации за четыре часа

Это бюджет времени для согласованного внутреннего прототипа, а не перечень задач, которые надо выполнять строго по одной. Пользователь и Ваня работают параллельно с Codex; frontend и презентация идут своими потоками. Зафиксированный объём не урезается молча при отставании.

## Рабочая организация

Один репозиторий и заранее согласованные модели. У пользователя — общие схемы, каркас, аккаунты и ядро; у Вани — файлы, AI и прикладные проверки. Каждый работает в своих каталогах. Общие контракты меняет владелец пакета 1; изменения сразу получает frontend.

Перед началом загрузить весь docs в общий репозиторий, клонировать его на рабочие машины и закрепить ноутбук Матвея, на котором уже проверен ChatGPT-вход CLI. Работать в отдельных ветках и получать main после готовых шагов. Подробная инструкция: [team-workflow.md](team-workflow.md). Новый API-бюджет не нужен. Учётные данные не копируются между ноутбуками через репозиторий.

| Время от старта | Пользователь | Ваня | Точка интеграции |
|---|---|---|---|
| 0–20 мин | Пакет 1: каркас, общие схемы, БД, API-контракт | Начало 5/10: минимальный AI-запрос, установка OCR, проверка окружения | Frontend получает контракт/примеры, health и адрес /api |
| 20–60 мин | Пакет 11 и основа 3: аккаунты, сессия, профиль | Пакет 5: архив, защищённое скачивание, извлечение/подтверждение | Реальный вход → загрузка → повторное скачивание через frontend |
| 60–110 мин | Пакеты 2/3: реестр, данные 12 стран, применимость/сравнение | Пакет 6: проверки и страховые поля | Хотя бы одно дело проходит реальные правила и показывает ошибку |
| 110–155 мин | Пакет 4: дела, привязки, чек-лист, формулы | Пакет 7 и начало 8: транзитные данные/проверки, письмо | Один документ в двух делах, разные даты и результаты |
| 155–190 мин | Пакет 9, завершение данных 12 сценариев и ядра | Завершение 8, пакет 10: комплекты образцов и сквозные проверки | Сравнение всех стран, письмо, событие и независимые прогрессы |
| 190–220 мин | Исправления своего ядра и стыков с frontend | Сквозная интеграция, два аккаунта, перезапуск/timeout | Все 12 направлений; чужие данные недоступны; архив сохранён |
| 220–240 мин | Фиксация рабочей версии, помощь репетиции | Runbook, запуск, контрольный показ | Без новых функций; демонстрационный сценарий воспроизводится |

AI-проба выполняется в начале на ноутбуке Матвея: найденный CLI и статус входа ещё не доказывают успешный запрос. Ваня параллельно готовит адаптер/контракт и локальные проверки; наличие у него такого же AI-входа не предполагается. Если лимит/сеть мешают, причина становится известна до финальной сборки; локальная проверка и явно обозначенный шаблон остаются рабочими. Заранее записанный результат не выдаётся за живой AI-вызов.

## Что проверять в первую очередь

1. Права на файл и дело, реальный вход/выход, сохранность кабинета.
2. Реальная обработка образца, сверка полей, замечание и исправление.
3. Применимость правил и чек-лист для всех 12 направлений.
4. Два независимых прогресса и отмена устаревшего положительного результата.
5. Транзит, письмо и ручная хронология в согласованном объёме.

Docker, оформление технической документации сверх runbook и расширения экспорта выполняются только после этих результатов. Удалять согласованные аккаунты, страны или проверки ради Docker не следует.

## Репетиция показа

- Войти пользователем A, показать личный архив и сохранённое дело.
- Сравнить направления, выбрать сценарий с конкретными подтверждёнными правилами.
- Загрузить SAMPLE-комплект с ошибкой даты/владельца/полиса, подтвердить поля и показать обоснованное замечание.
- Загрузить исправленный образец, повторить проверку, показать изменение готовности без автоматической подачи.
- Использовать тот же паспорт в другом деле с другими датами: результат проверки зависит от поездки.
- Проверить пересадку в покрытой стране и непокрытый маршрут: показать разницу в полноте данных.
- Получить реальный черновик AI при доступном лимите, отредактировать/скачать текст; при недоступности явно показать резервный режим.
- Добавить ручное событие подачи/возврата паспорта и показать независимый процесс/неизвестный исход.
- Войти пользователем B в другом браузерном профиле: архив A недоступен.
- Перезапустить backend и снова открыть сохранённый файл A.

Используются только вымышленные данные. Презентация может показывать перспективы, но функция за пределами демо не называется уже работающей.
